# Plan 05-01: Suporte a Múltiplos Provedores de IA

<objective>
Implementar a abstração e integração dos provedores OpenAI (GPT-4o), Anthropic (Claude 3.5) e Ollama Local (100% offline) via `AnswerProvider`, e adicionar o seletor visual de provedor com campos de chaves no painel de opções.
</objective>

<must_haves>
- [ ] Tipos compartilhados (`settings.ts`) expandidos para incluir `aiProvider`, `openaiApiKey`, `anthropicApiKey`, `ollamaEndpoint` e `ollamaModel`
- [ ] Provedores concretos `OpenAIProvider`, `AnthropicProvider` e `OllamaProvider` em `apps/orchestrator/src/services/`
- [ ] `AnswerProviderManager` para alternar dinamicamente o provedor ativo no Orquestrador
- [ ] Formulário de opções (`settings-form.tsx`) atualizado com seletor dropdown e inputs condicionais por provedor
</must_haves>

<tasks>

<task id="task-1">
  <title>Expandir Tipos de Configurações em shared-types</title>
  <read_first>
    - packages/shared-types/src/settings.ts
    - .planning/phases/05-suporte-a-novos-provedores-de-ia/05-CONTEXT.md
  </read_first>
  <action>
    1. Em `packages/shared-types/src/settings.ts`:
       - Definir `type AIProvider = 'gemini' | 'openai' | 'anthropic' | 'ollama';`
       - Adicionar campos em `Settings`:
         - `aiProvider?: AIProvider;`
         - `openaiApiKey?: string;`
         - `anthropicApiKey?: string;`
         - `ollamaEndpoint?: string;`
         - `ollamaModel?: string;`
  </action>
  <acceptance_criteria>
    - `packages/shared-types/src/settings.ts` exporta o tipo `AIProvider` e os novos campos de `Settings`
  </acceptance_criteria>
</task>

<task id="task-2">
  <title>Criar Provedores OpenAI, Anthropic e Ollama no Orquestrador</title>
  <read_first>
    - apps/orchestrator/src/services/answer-provider.ts
    - apps/orchestrator/src/services/gemini.ts
  </read_first>
  <action>
    1. Criar `apps/orchestrator/src/services/openai.ts`:
       - Implementar `OpenAIProvider implements AnswerProvider` consumindo `https://api.openai.com/v1/chat/completions` via `fetch` em streaming SSE.
    2. Criar `apps/orchestrator/src/services/anthropic.ts`:
       - Implementar `AnthropicProvider implements AnswerProvider` consumindo `https://api.anthropic.com/v1/messages` via `fetch` em streaming SSE.
    3. Criar `apps/orchestrator/src/services/ollama.ts`:
       - Implementar `OllamaProvider implements AnswerProvider` consumindo endpoint REST local (`/api/generate`) via `fetch` com streaming NDJSON/JSON Lines.
    4. Criar `apps/orchestrator/src/services/provider-manager.ts`:
       - Implementar `AnswerProviderManager` que encapsula Gemini, OpenAI, Anthropic e Ollama, alternando o provedor ativo baseado nas `Settings`.
  </action>
  <acceptance_criteria>
    - Os arquivos `openai.ts`, `anthropic.ts`, `ollama.ts` e `provider-manager.ts` implementam a interface `AnswerProvider` com suporte a streaming e cancelamento por `AbortSignal`
  </acceptance_criteria>
</task>

<task id="task-3">
  <title>Atualizar Formulário de Opções e Integrar no Orquestrador</title>
  <read_first>
    - apps/chrome-extension/src/shared/settings-form.tsx
    - apps/orchestrator/src/server.ts
  </read_first>
  <action>
    1. Em `apps/chrome-extension/src/shared/settings-form.tsx`:
       - Adicionar seletor dropdown para o Provedor de IA ativo (`aiProvider`).
       - Exibir dinamicamente os inputs de chave de API / URL baseados no provedor escolhido (Gemini, OpenAI, Anthropic, Ollama).
    2. Em `apps/orchestrator/src/server.ts`:
       - Substituir `geminiProvider` por `providerManager` na instanciação e no handler `settings.update`.
  </action>
  <acceptance_criteria>
    - `settings-form.tsx` exibe o seletor visual de provedor e salva as opções no `chrome.storage.local`
    - `server.ts` utiliza `providerManager` e alterna o provedor em tempo real sem reiniciar o servidor
  </acceptance_criteria>
</task>
